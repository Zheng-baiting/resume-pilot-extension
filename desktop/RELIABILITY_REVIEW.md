检查日期：2026-09-07。范围：扩展到桌面端同步、岗位链接、评分、队列、JSON 存储、原生通信和桌面界面。未使用个人简历或向企业提交申请。

## 已修复

| 问题 | 修复与验证 |
| --- | --- |
| 桌面同步按域名和路径去重，丢失同标题不同查询参数/井号路由的岗位 | 同步保留完整链接；桌面规范化保留 hash 路由，拒绝非 HTTP(S) 或含凭据的 URL。新增不同岗位链接测试 |
| 重建队列清空已处理状态，可能重复申请 | 保留已处理、处理中、重试记录，按历史记录继续计算企业上限。测试覆盖重复重建和禁止覆盖终态结果 |
| 修改队列上限仍使用旧 limit；0 分、0 待遇被默认值覆盖 | 统一数值校验及优先级，支持显式 0；部分更新资料不清空已有待遇条件 |
| 重连后失去域名冷却时间或忽略处理中任务 | 领取时读取持久化记录，检查同域名任务及 retryAt；重新核验最新城市、过期等硬条件 |
| 写 JSON 前先删除旧文件；一次失败导致后续全部写入失败 | 改为临时文件原子替换，失败保留旧文件，后续写入链可恢复；通过模拟替换失败验证 |
| stdin 数据事件并发处理造成读写覆盖 | 单宿主顺序消费完整帧，遇超长或截断帧终止；测试覆盖连续分片导入 |
| 桌面“领取”将任务置为处理中，但没有浏览器接管 | 改为只读预览，说明实际投递需从扩展启动；修正误导性的双向同步提示 |

## 待完成（按优先级）

1. **桌面到浏览器执行闭环**：接通任务领取、官网状态确认、最终结果回传和中断恢复；只有收到官网成功证据才能标为 submitted。目前 DESKTOP_NEXT_JOB / DESKTOP_REPORT_RESULT 有消息入口，但扩展投递状态机尚未调用它们。
2. **跨进程事务与崩溃恢复**：桌面与 Native Host 共享 JSON，但各自维护服务实例。原子替换不等同于跨进程事务；需采用单写入进程或事务数据库，并测试两个进程同时领取任务不会重复。
3. **真实官网验收**：现有十公司流程测试主要以固定 HTML 模拟官网结构，尚不能证明真实站点登录、筛选、翻页、填写到成功回执全链路稳定。应记录逐站核验时间、失败原因和支持边界。
4. **原生消息大小与恢复**：发送端已有 1MB 响应保护，但大岗位库快照需要分页；重启后的指数退避失败次数仍需持久化；结果不明的处理中任务应提供人工核验后的恢复操作。
5. **发行质量**：浏览器测试依赖的可复现配置、签名安装包、升级和卸载验收仍待完善；对外发布前明确开发预览与稳定插件的区别。
